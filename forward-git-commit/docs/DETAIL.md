# 提交并推送（forward-git-commit）

在 DSH 会话标题栏右侧加一个「提交」按钮。点开后弹窗显示**当前分支**、**改动文件数**和**远端**，
输入提交信息，点「提交并推送」即完成 `git add -A` → `git commit` → `git push`。

## 按钮在哪

会话标题栏那一行的右侧，和「后台任务」等控件同一排——就在「对话 / 上下文 / 编队」标签行的上方。
它是会话级控件：切换会话时弹窗自动关闭，不会把上一个仓库的表单带过来。

## 弹窗里有什么

| 字段 | 说明 |
|---|---|
| 分支 | 当前分支名；游离 HEAD 时显示「游离 HEAD」，此时不允许提交 |
| 改动 | 未提交文件总数，并标出已暂存与未跟踪的数量；干净时显示「没有改动」 |
| 远端 | `origin`（没有则取第一个 remote）；一个都没有时显示「未配置」并拒绝推送 |
| 提交信息 | 必填。`⌘/Ctrl + Enter` 直接执行 |

成功后弹窗显示提交短哈希与分支名，1.6 秒后自动关闭；分支是首次推送时会注明「（首次发布）」。

## 行为边界

- **暂存范围是整个工作区**（`git add -A`）。按钮的承诺是「把现在的改动提交上去」，所以不会漏掉
  你以为已经暂存的改动；弹窗上的文件数就是这个范围。
- **不会**执行 `push --force`、`reset --hard`、`clean`、`checkout --`。一键按钮必须能安全地误触；
  推送被拒时如实报错，绝不靠改写历史来「解决」。
- 推送被拒（远端有新提交）时，**提交已经落地**，错误信息会明确写出提交哈希，并提示先 pull / rebase；
  修好后重试只会再推一次，不会产生第二个提交。
- 提交信息经 stdin 传给 `git commit -F -`，因此引号、换行、以 `-` 开头的内容都按普通文本处理。
- 所有 git 子进程经 `ctx.subprocess` 启动：解析可执行文件、限制输出、超时终止、并清除环境里
  `*TOKEN*` / `*SECRET*` 形状的变量。子进程设置了 `GIT_TERMINAL_PROMPT=0`，凭据缺失时立即失败
  而不是挂住等输入。

## 要求

- 会话工作区必须位于一个 Git 仓库内（`git rev-parse --show-toplevel` 能找到根目录，子目录也可以）。
- 仓库必须配置了远端才能推送。
- 本机 `git` 需已有可用凭据（SSH key 或凭据助手）；插件不读取、不保存任何凭据。
